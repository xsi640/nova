# 阶段 3B：任务拆解

## 1. 实现范围与顺序说明

本任务文档严格以 `tech-architecture.md` 为输入，不修改已确认的需求、UX、UI 或架构。用户明确要求本次只拆分任务、不写代码，因此所有任务初始状态均为“待处理”。

本次不生成 `api-design.md`；该文档在用户后续明确需要接口细则时再单独开展。

### 最小可运行闭环

最小闭环是“用户完成首次配置后，可以持续进行本地保存的文字对话”：

```text
TASK-001 项目骨架
  → TASK-002 SQLite 数据库
  → TASK-003 本地命令边界
  → TASK-004 API 配置
  → TASK-005 虚拟女友设定与引导
  → TASK-006 应用壳与页面入口
  → TASK-007 文字对话
```

完成闭环后，用户可以：配置并测试对话 API、设置虚拟女友、发送文字、看到回复、重启后继续同一条聊天时间线，并在 API 失败时得到恢复入口。

其余功能按以下顺序推进：语音交互 → 长期记忆 → 日程 → 后台主动陪伴 → 数据导出 → 跨平台验证。

## 3. 任务依赖与并行分组

### 并行组 A：工程与本地基础

- TASK-001 为所有实现工作的起点。
- TASK-002 与 TASK-003 共同建立本地存储和前后端命令边界；TASK-003 可在 TASK-002 的接口约定确定后并行推进，但必须在数据库初始化完成后验证数据命令。

### 并行组 B：首次可用配置与外壳

- TASK-004（AI 服务配置）与 TASK-006（桌面应用壳）可在 TASK-002、TASK-003 后并行。
- TASK-005 依赖 TASK-004，确保首次引导包含真实的 API 测试。

### 关键路径：文字陪伴闭环

```text
TASK-001 → TASK-002 → TASK-003 → TASK-004 → TASK-005 → TASK-007
                                  └──────────→ TASK-006 ────┘
```

TASK-007 完成即达到最小可运行闭环。

### 并行组 C：聊天能力扩展

- TASK-008（语音）、TASK-009（记忆）和 TASK-010（日程）均依赖 TASK-007，可并行开发。
- TASK-011 依赖 TASK-010。
- TASK-012 依赖 TASK-007，并与 TASK-011 并行，但必须读取 TASK-014 的免打扰设置约定。
- TASK-013 依赖 TASK-009，确保导出覆盖已确认的聊天与记忆数据。
- TASK-014 可在 TASK-006 后并行开始，并在 TASK-012 前完成其免打扰部分。

### 并行组 D：跨平台收口

- TASK-015 在核心模块具备可运行实现后执行，是发布前的验证任务。
- TASK-015 位于项目关键路径末端；如发现平台能力缺口，应回到对应模块任务处理，不在验证任务中扩大范围。
