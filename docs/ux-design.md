# 阶段 2A：UX 设计

## 1. UX 设计目标

**UX-001：长期陪伴型桌面交互体验。**

- 让用户快速完成虚拟女友设定与 API 配置，并开始首次交流。
- 让聊天成为单一、连续的长期对话时间线，而不是多个彼此割裂的会话。
- 让主动陪伴以自然的对话开场进入聊天，而不是作为普通提醒打断用户。
- 将记忆和日程能力融入聊天，同时保留独立的管理入口。
- 在 API、网络、麦克风和日程解析出现问题时，为用户提供明确的恢复路径。

## 2. 用户角色和使用场景

### USER-001：需要长期情感陪伴的单身成年人

用户有基本桌面应用使用能力，愿意让应用在后台驻留，并希望通过文字或语音与虚拟女友保持连续互动。

主要场景：

- 日常打开应用聊天。
- 孤独或情绪低落时倾诉并获得聆听和安慰。
- 使用按住说话方式进行语音交流。
- 让虚拟女友记住个人信息和长期互动内容。
- 用自然语言创建、查看、修改和删除应用内日程。
- 在电脑操作长期低频时，从桌面提示进入虚拟女友主动发起的对话。

## 3. 用户主流程

### FLOW-001：首次使用与开始聊天

1. 用户启动应用。
2. 系统显示 `PAGE-001` 首次使用引导。
3. 用户设置虚拟女友的姓名、性格和说话方式。
4. 用户配置 OpenAI 兼容 API。
5. 用户测试 API。
6. API 测试通过后，用户进入 `PAGE-002` 聊天首页。
7. 虚拟女友发送首次欢迎消息，用户开始长期对话。

### FLOW-002：文字聊天

1. 用户在 `PAGE-002` 输入文字并发送。
2. 页面追加用户消息，进入 AI 响应中状态。
3. 虚拟女友返回文字消息。
4. 语音回复默认自动播放，同时始终保留文字和手动播放入口。
5. 对话中的长期信息按规则自动形成记忆，并在聊天中给出已记住反馈。

### FLOW-003：按住说话

1. 用户在 `PAGE-002` 按住麦克风按钮，页面进入录音状态。
2. 用户松开按钮，系统识别语音内容。
3. 系统展示识别出的文字。
4. 用户可以编辑、确认发送或取消。
5. 用户确认后，流程进入 `FLOW-002` 的 AI 响应阶段。

### FLOW-004：长期记忆管理

1. 用户从侧边栏进入 `PAGE-003` 记忆页面。
2. 用户查看自动保存的记忆列表。
3. 用户可编辑或删除某条记忆。
4. 用户可查看该记忆的来源消息。
5. 用户可导出自己的聊天记录和记忆；导出格式由后续技术设计确定。

### FLOW-005：对话式日程管理

1. 用户在 `PAGE-002` 表达日程需求。
2. 虚拟女友识别日程事项、时间等信息。
3. 信息不完整时，虚拟女友继续追问缺失信息。
4. 信息完整时，虚拟女友生成日程确认卡。
5. 用户确认后，系统正式创建日程并反馈成功。
6. 用户可在聊天中或 `PAGE-004` 日程页面查看、修改、删除日程。
7. 日程页面按日期分组展示日程。
8. 到达日程时间后，系统显示日程提醒；日程提醒不受免打扰时间影响。

### FLOW-006：后台主动陪伴

1. 应用在后台运行。
2. 系统检测到鼠标、键盘操作持续约 30 分钟非常不频繁。
3. 若当前不在免打扰时间范围内，虚拟女友生成自然的主动消息。
4. 系统显示桌面提示。
5. 用户点击提示后，应用打开 `PAGE-002`，并展示该条主动消息。
6. 用户继续对话或暂时离开。
7. 用户未点击提示时，该条主动消息仍保留在长期聊天时间线中，但不再次弹出同一条通知。

## 4. 分支流程

### BRANCH-001：主动陪伴处于免打扰时间

- 系统不显示主动陪伴提示，也不生成对应的主动对话消息。
- 用户主动打开应用和发送消息不受影响。
- 日程提醒仍按原计划发送。

### BRANCH-002：日程信息不完整或用户不确认

- 信息不完整时，虚拟女友继续追问，不显示确认卡。
- 用户可修改确认卡内容。
- 用户取消确认时，不创建日程，并返回正常聊天。

### BRANCH-003：API 配置或调用失败

- 首次配置失败时，用户停留在 `PAGE-001` 并可修改配置、重新测试。
- 日常调用失败时，`PAGE-002` 说明错误原因，并提供重试和前往 `PAGE-005` 设置页的入口。
- 本地聊天记录、记忆和日程保持可查看。

### BRANCH-004：危机情绪表达

- 虚拟女友继续聆听和安慰用户。
- 第一版不提供独立紧急帮助入口。
- 危机情绪的识别条件、具体应答话术和连续陪伴策略延后讨论。

## 5. 异常、中断和返回路径

### ERROR-001：API 未配置

- 聊天页面提示当前无法开始 AI 对话。
- 用户可直接进入 `PAGE-005` 配置 API。
- 已保存的本地数据仍可访问。

### ERROR-002：API 或网络不可用

- 保留用户已输入但未成功发送的内容，以及已有本地历史数据。
- 显示失败原因、重试入口和 API 设置入口。

### ERROR-003：麦克风不可用

- 显示麦克风权限或设备异常说明。
- 提供重试方式。
- 用户可以继续使用文字输入。

### ERROR-004：语音识别或语音播放失败

- 语音识别失败时，保留重新录音和使用文字输入的入口。
- 语音播放失败时，文字回复仍完整可读，并提供重新播放入口。

### ERROR-005：用户中断操作或返回应用

- 用户离开页面时已发送消息和已生成内容保留。
- 用户返回后继续同一条长期对话时间线，不产生新会话。
- 未点击的主动消息保留在聊天时间线中。

### ERROR-006：日程内容无法解析

- 系统不创建不确定或错误的日程。
- 虚拟女友明确说明缺失或无法理解的信息，并继续询问。

## 6. 页面职责

| 编号 | 页面 | 职责 |
|---|---|---|
| PAGE-001 | 首次使用引导 | 完成虚拟女友设定、OpenAI 兼容 API 配置和 API 测试 |
| PAGE-002 | 聊天首页 | 承载长期对话、文字与按住说话交互、文字和语音回复、记忆反馈、日程确认卡和主动消息 |
| PAGE-003 | 记忆页面 | 查看、编辑、删除记忆，并查看记忆来源消息 |
| PAGE-004 | 日程页面 | 按日期分组查看应用内日程，并支持修改和删除 |
| PAGE-005 | 设置页面 | 配置与测试 API、设置免打扰时间范围、处理语音相关设置和数据管理入口 |

边界说明：

- 桌面主动陪伴提示是全局系统入口，不是独立业务页面；点击后统一进入 `PAGE-002`。
- 日程确认卡、记忆已保存反馈和危机情绪陪伴均在 `PAGE-002` 内完成，不增加独立页面。
- `PAGE-003` 只管理记忆，不负责日程或 API 配置。
- `PAGE-004` 只管理应用内日程，不读取或同步系统日历。
- `PAGE-005` 只负责设置和数据管理入口，不承担日常对话。

## 7. 页面关系

```text
PAGE-001 首次使用引导
        │ 配置并测试 API 成功
        ▼
PAGE-002 聊天首页
   ┌────┼────┬────┐
   ▼    ▼    ▼    ▼
PAGE-003 PAGE-004 PAGE-005 桌面主动陪伴提示
记忆页    日程页    设置页            │
                                    └─ 点击后进入 PAGE-002
```

- `PAGE-002` 是日常使用的首页和核心入口。
- `PAGE-003`、`PAGE-004`、`PAGE-005` 通过侧边栏进入。
- API 异常时，`PAGE-002` 和 `PAGE-001` 都可跳转至 `PAGE-005`。
- 日程提醒、主动陪伴提示均可以将用户带回 `PAGE-002`，但日程提醒的具体跳转交互在 UI 阶段细化。

## 11. UX 验收标准

- 新用户能够完成虚拟女友设定、API 配置和测试，并进入首次聊天。
- API 测试或日常调用失败时，用户知道如何重试或修改配置，且本地数据不丢失。
- 用户能在同一条长期对话时间线中持续交流。
- 用户可以使用文字和按住说话两种方式完成对话；语音识别结果须经用户确认或编辑后发送。
- AI 回复默认播放语音，同时始终有文字内容可阅读与重新播放。
- 用户能明确区分日程待确认和日程已创建，并能完成日程的查看、修改、删除和提醒。
- 用户可以查看、编辑、删除记忆并定位其来源消息。
- 主动陪伴通过桌面提示进入聊天，未点击时消息仍保留在聊天记录中且不重复弹出同一通知。
- 免打扰时间内不触发主动陪伴；日程提醒不受免打扰影响。
- API、网络、麦克风、语音和日程解析异常均有可理解的恢复路径。

## 13. 人工确认结论

- 用户已确认首次引导顺序：设置虚拟女友、配置并测试 API、进入首次聊天。
- 用户已确认聊天、记忆、日程、设置为侧边栏中的四个主要入口，聊天是日常首页。
- 用户已确认主动陪伴通过桌面提示进入聊天，点击后展示虚拟女友已经发出的主动消息；未点击时消息保留在长期聊天中且不重复弹出。
- 用户已确认语音回复默认自动播放，麦克风使用按住说话方式，识别文本可编辑确认后发送。
- 用户已确认日程通过对话生成确认卡后创建，支持查看、修改、删除和提醒，并以按日期分组的列表展示。
- 用户已确认记忆默认自动保存，用户可在记忆页面查看、编辑、删除并查看来源消息。
- 用户已确认 API 或网络异常时保留本地数据，在聊天页提供错误说明和 API 设置入口。
- 用户已确认免打扰支持时间范围设置，仅影响主动陪伴，不影响日程提醒。
- UX 草稿已通过完整性与一致性检查；延期事项已记录处理方式。阶段 2A 完成，可进入阶段 2B。
