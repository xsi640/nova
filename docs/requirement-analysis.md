# 阶段 1：需求分析

## 1. 项目概述

本项目要开发一款面向单身成年人的跨平台桌面端 AI 虚拟女友应用，为有孤独、倾诉和情绪陪伴需求的用户提供可长期使用的陪伴体验。

用户可以自定义虚拟女友的姓名、性格和说话方式，通过文字或麦克风输入进行交流，并获得文字和语音回复。应用保存长期记忆，支持后台主动参与对话，以及通过自然语言创建和管理应用内日程。

产品定位：能够记住用户、理解长期互动，并以自然方式主动参与日常交流的桌面端 AI 情感陪伴助手。

## 2. 目标用户

- 单身成年人
- 需要情感陪伴、倾诉和被倾听的人
- 愿意长期使用 AI 陪伴产品的人
- 具备基本桌面应用使用能力，并接受应用在后台运行的人

主要使用场景包括日常聊天、孤独时倾诉、情绪低落时寻求安慰，以及通过对话安排个人日程。

## 3. 要解决的问题

- 用户缺少稳定、随时可交流的倾听对象。
- 用户在孤独或情绪低落时缺少持续的陪伴和安慰。
- 普通聊天工具缺少长期记忆，难以形成连续的关系体验。
- 用户希望用自然对话完成日程创建和提醒，而不是使用独立的表单式工具。

## 4. 需求目标

1. 提供自然的文字和语音交流体验。
2. 允许用户创建并保存虚拟女友的姓名、性格和说话方式。
3. 保存与用户长期互动相关的记忆，并在后续对话中使用。
4. 当电脑上的鼠标、键盘操作持续约 30 分钟非常不频繁时，以自然方式主动参与或开启对话，而不是作为单纯的提醒通知。
5. 允许用户设置免打扰时间范围，控制主动陪伴的时间。
6. 允许用户通过对话创建、查看、修改和删除应用内日程，并按日程进行提醒。
7. 将聊天记录、记忆、用户设定和日程优先保存在用户本机。
8. 支持 Windows 和 macOS 主流版本，并支持应用后台运行。
9. AI 能力不要求本地模型运行，应用应支持配置 OpenAI 兼容 API。
10. 在用户表达危机情绪时，虚拟女友应尽力聆听和安慰。

## 5. 模块边界说明

| 模块 | 职责 |
|---|---|
| 虚拟女友设定 | 管理姓名、性格和说话方式等个性化信息 |
| 对话交互 | 处理文字输入、麦克风输入，以及文字和语音输出 |
| 长期记忆 | 保存与用户及其长期互动相关的信息，并为对话提供记忆上下文 |
| 主动陪伴 | 根据低频电脑操作状态，在非免打扰时间自然参与或开启对话 |
| 日程管理 | 通过对话创建、查看、修改、删除应用内日程，并负责日程提醒 |
| 本地数据 | 保存聊天记录、虚拟女友设定、记忆和日程，并支持用户管理相关数据 |
| 桌面运行与通知 | 支持 Windows/macOS 主流版本、后台驻留和必要的提醒呈现 |
| AI 服务配置 | 管理 OpenAI 兼容 API 的配置和调用，不负责保存业务数据本身 |

边界规则：

- 长期记忆只负责信息保存和调用，不负责决定何时主动联系用户。
- 主动陪伴负责参与对话的时机和方式，不负责创建或修改日程。
- 日程管理只处理应用内日程，不读取或同步 Windows/macOS 系统日历。
- 虚拟女友设定影响对话表现，但不直接修改聊天记录、记忆或日程。
- 本地数据模块负责业务数据的本地持久化；AI 服务配置模块负责外部模型接口配置，两者职责分离。
- 第一版不包含外貌自定义和视频互动。
- 记忆、聊天记录和日程均归属于当前用户及其虚拟女友实例，不能脱离用户主体单独存在。

## 6. 成功标准

第一版完成后，用户应能够：

- 在 Windows 或 macOS 主流版本上安装并运行应用。
- 完成虚拟女友姓名、性格和说话方式的设置。
- 使用文字或麦克风发起交流，并同时获得文字和语音回复。
- 关闭并重新打开应用后，仍能看到保留的设定、聊天记录和记忆。
- 查看、修改、删除和导出自己的聊天记录及记忆。
- 通过自然语言完成应用内日程的创建、查看、修改和删除。
- 在后台运行时，在允许的时间范围内获得自然的主动陪伴和日程提醒。
- 在表达危机情绪时获得持续的倾听和安慰。

产品使用方向上的成功表现是：用户愿意让应用常驻后台，并持续长期使用。

## 7. 范围与边界

### 必做

- Windows/macOS 主流版本的跨平台桌面应用
- 虚拟女友姓名、性格和说话方式自定义
- 文字输入与输出
- 麦克风输入
- 语音输出
- 长期记忆
- 聊天记录和记忆的查看、修改、删除、导出
- 后台主动参与对话
- 免打扰时间范围设置
- 通过对话管理应用内日程
- 日程提醒
- 本地保存聊天记录、记忆、设定和日程
- OpenAI 兼容 API 配置
- 危机情绪下的聆听和安慰

### 暂不做

- 视频互动
- 外貌自定义
- 读取或同步 Windows/macOS 系统日历
- 本地 AI 模型运行
- 云端业务数据存储和多设备同步
- 独立的紧急帮助入口

## 8. 约束与风险

### 主要约束

- 必须支持 Windows 和 macOS 主流版本。
- 应用需要支持后台驻留、低频操作检测和免打扰时间控制。
- 聊天记录、记忆、设定和日程以本地存储为主。
- AI 不在本地运行，需要用户配置可用的 OpenAI 兼容 API。
- 日程只属于应用自身，不依赖系统日历。

### 主要风险

- Windows 和 macOS 对后台运行、开机启动、麦克风权限和通知能力的处理存在差异。
- 外部 API 的可用性、兼容性、费用和网络状况会影响核心对话体验。
- 用户的聊天记录和长期记忆包含敏感情感信息，本地数据保护和导出删除机制需要谨慎设计。
- 记忆可能错误、重复或保存不应长期保留的信息。
- 主动参与对话过于频繁或时机不自然，可能造成打扰，降低长期留存。
- 不设置恋爱关系限制并允许强化依赖式表达，可能增加情绪依赖、误导和合规风险。
- 第一版不提供紧急帮助入口，危机情绪应答的识别条件和具体话术仍需后续详细设计。

## 10. 人工确认结论

- 用户已确认产品面向需要情感陪伴的单身成年人。
- 用户已确认第一版的核心能力：文字和语音交互、长期记忆、后台自然主动参与对话、免打扰时间范围、对话式应用内日程管理。
- 用户已确认虚拟女友支持姓名、性格和说话方式自定义，外貌自定义和视频互动暂不纳入第一版。
- 用户已确认数据本地保存，AI 使用可配置的 OpenAI 兼容 API，不要求本地 AI 模型。
- 用户已确认支持 Windows 和 macOS 主流版本。
- 用户已确认危机情绪下以聆听和安慰为主要处理方式，第一版不提供独立紧急帮助入口；具体安全机制保留为后续详细讨论事项。
- 阶段完成判断：核心目标用户、问题、需求目标、模块边界、成功标准、范围和主要风险已明确；延期事项已记录处理方式，可以进入后续阶段。
